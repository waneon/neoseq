# Representation Architecture

## Purpose

Neoseq keeps one representation for each kind of truth. User intent, causal
state, executable work, read models, and transport records have different
lifetimes and must not impersonate one another.

```text
Command intent
    -> normalized Transition
    -> one causal document transaction
    -> deterministic Projection + typed conflicts
    -> disposable indexes and UI views

Raw SPARQL ---------\
                     -> LogicalQuery -> budgeted execution
Builder QueryPlan --/
```

## Canonical State

The Loro document is the sole graph authority. Stable entity IDs, property
fields, query documents, tag references, and outline trees live there. SQL
rows, RDF triples, text indexes, query results, command caches, local undo
metadata, presence, and transport cursors do not.

The causal document kernel owns schema identity and import/export mechanics.
An interactive replica adds command preparation, local history, persistence,
and projections. A server graph adds only validation, differential exchange,
quota measurement, and durable-before-adopt candidates. Neither machine gives
its ephemeral state canonical meaning.

Server validation is structural and merge-closed. It verifies causal container
and envelope invariants without invoking the query compiler or current client
projection; opaque future query plans therefore survive synchronization even
when this server cannot execute them.

## Write Representation

`Command` is an input language, not an execution plan. The core validates each
intent against one document revision and lowers it to an immutable normalized
`Transition`. A transition contains typed primitive operations and derives its
write footprint, timestamp touches, history scope, result shape, and semantic
event from those operations.

Mutation never reinterprets the original command. Structural reads that choose
IDs, positions, or affected nodes happen during preparation. Ordered tree moves
carry stable destination identities, so application issues blind moves without
reading the hierarchy again. One accepted transition produces one Loro
transaction, one local undo item, at most one durable update, and one semantic
event. A batch is the sole orchestration exception: it owns a bounded command
sequence, preflights it against an isolated evolving candidate, then re-lowers
each step against the live state inside one outer transaction. This second
lowering is necessary because CRDT tree IDs generated by the disposable
candidate are not portable authority.

Execution carries the closed `SemanticEvent` vocabulary directly. Whether
durability work exists is represented by the update bytes themselves; the core
does not carry an independent duplicate flag that could disagree with them.

## Merge and Projection

Synchronization is valid-state CRDT merge, not distributed transaction
validation. The required law is:

```text
valid(base -> left) and valid(base -> right)
    => merge(left, right) succeeds in either delivery order
```

Checks that protect an individual command remain admission checks. Aggregate
conditions that concurrent branches can exceed are projection rules. The raw
causal entries remain present; a deterministic bounded view is published and a
typed `GraphConflict` names the hidden or ambiguous participants. Resolving a
conflict uses an ordinary command. Malformed storage shapes remain corruption
and may be rejected or quarantined.

Property presence and identity are one outer map entry per key. Its value is a
regular Loro map whose immutable shape and single, set, or document payload form
one field generation. Deleting the outer reference makes concurrent edits within
that child inert; recreation installs a fresh generation.

Concurrent creation of an absent key is deliberately whole-container LWW. One
regular child wins with its shape and initial payload intact, preventing hybrid
fields even when replicas chose incompatible shapes. The same arbitration also
chooses one of two same-shape initial payloads. Fine-grained payload edits merge
only after both replicas share the winning generation.

Projection is a pure function of canonical state. Ordering uses semantic keys
plus stable IDs, never map iteration or arrival order. A conflict is therefore
identical after reordered or duplicate delivery, and deleting an earlier item
deterministically promotes the next preserved item.

One `ProjectedGraph` pass produces values, quarantine, and typed conflicts
together. It reads each page and tag header once and visits each visible block
once; `GraphSnapshot` and `GraphSummary` are views of that same result rather
than independent interpretations of the causal document.

## Query Representation

The query builder persists a versioned typed `QueryPlan`; advanced input may
provide raw SPARQL. Both are source forms and compile once to `LogicalQuery`,
the only representation validated, budgeted, and executed. Generated SPARQL is
an explanation or compatibility artifact, never a second semantic authority.
Bindings remain typed values and enter algebraically rather than through text
substitution.

The RDF store and text accelerators are frontier-keyed projections. They may be
dropped and rebuilt from the graph document without losing information. Their
invalidation is either a full rebuild or a set of affected publication units;
an incremental delta gives each unit exactly one upsert-or-remove state.

## Limits and Failure

Limits belong to the narrowest boundary that can enforce them without breaking
merge closure:

- command shape and per-edit size at local admission;
- update, frame, reconstructed graph, and storage bytes at transport or
  persistence admission;
- row, operator, and evaluation work at query execution;
- visible collection sizes at deterministic projection.

Typed conflicts describe valid collaborative states that need a user choice.
Quarantine describes unreadable data that is omitted from a projection.
Protocol and storage errors describe failure to cross an external boundary.
These states are not collapsed into one generic validation error.

## Evolution Rules

- Add a new command by defining its lowering; do not add parallel validation,
  mutation, timestamp, history, and event match trees.
- Add a new builder feature by extending the typed plan and its compiler; do
  not teach execution a second query language.
- A new aggregate invariant must include a reordered two-branch merge law.
- A cache or index must carry the canonical frontier that produced it.
- Server code may depend on the causal document kernel, never on interactive
  undo, command caches, graph projection, or query execution semantics.
- A representation is retained only when removing it would lose information,
  an invariant, or an external compatibility boundary.
